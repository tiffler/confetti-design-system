# Color

Every swatch below is read from `build/portfolio/tokens.json` for the theme and mode
selected in the toolbar — nothing on this page is hardcoded. Switch **Mode** in the
toolbar to see the semantic layer repoint while the token names stay put.

Swatches run **lightest to darkest** by relative luminance. Translucent tokens are
flattened onto the page surface first, since that is what renders.

**Only combinations that clear 4.5:1 appear here** — the AA threshold for body text.
Anything below it is left off the page entirely rather than shown as a failure, so
every ratio you see is one you can use. Specimens render on `surface-page` rather than
the Storybook docs canvas, so the text colors are measured against the surface they
are actually meant for.

## Surfaces

The elevation ramp. `backdrop` is the recessed mat a step below page (app frames,
control tracks), `page` is the baseline, `raised` is canvas and widget surfaces,
`panel` is toolbar and sidebar chrome, `card` is the contrast interior.

## Status

Success and danger. Unlike the accents, these are not decorative and not brand: green
means one thing, so status sits on the **mode** axis and every theme inherits the same
pair rather than repointing it. Each has a filled pair (`bg` + `fg`) and a `text` step
for the same status set as type — the fill can hold its white label on any page, but the
same green as text drops to 2.43:1 on the card surface, so `text` lifts in dark mode for
the same reason `text.accent` does.

## Semantic

Every semantic colour role in one place. The sections above walk through them by job;
this is the index — searchable, sortable, and read from the same generated file, so it
cannot fall behind the build.

This is the layer to consume. A role names what a colour is *for*, so it survives a
re-skin: `surface-raised` still means "the canvas step above page" when the paint under
it changes, while `porcelain-50` stops being true the moment it does.
